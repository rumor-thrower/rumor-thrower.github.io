## The problem

**Background.** I wanted to analyze how well works perform by tag, measured by view count, in a tagged collection of web-novel metadata. The question was which tag a new work should carry to perform well. A common shortcut was to rank tags inside the top-ranked works. The ranking looked clear, but it answers a different question: which tag performs well among works that already succeeded. The example below uses synthetic data with the same structure (one tag per work, integer view counts). The tags A, B, and C are placeholders, and the numbers are illustrative, not measurements from any real platform.

Suppose you want to know which tag to use if you want a work to do well. A common shortcut is to take the top N works by views and rank tags inside that set. The shortcut feels safe because it looks only at the successful works. It is wrong for the question you actually asked. The top-N set already conditions on success, so the tag counts in it do not tell you how a tag performs across all works that carry it.

This post reproduces the effect with synthetic data. The numbers below are generated by the script, not measured on any real platform.

## Attempts, in order

1. **Rank tags by mean views.** The mean is pulled up by a few extreme works, so this ranks which tag caught a mega-hit. Tag B has the highest mean (6792.1) while its median is the lowest of the three (871.0). The mean says B; the median does not.
2. **Rank tags inside the top 1,000.** Tag B takes 647 of the 1,000 slots, but that is 6.5% of its 9,964 works. Tag A takes 159 slots, which is 0.4% of its 39,779 works. Counting slots inside the cut makes B look dominant, and it hides how rarely A reaches the cut at all.
3. **Use the full population for each tag, with n.** Median views over every work carrying the tag give A 1823.0 and B 871.0. This is the only one of the three denominators that answers the question of which tag to use.

Attempts 1 and 2 are the same mistake in two forms. Both use a denominator that is already a set of winners.

## Conclusion: the alternative to use

Report, for each tag, the median over every work that carries it, and always show n next to it. If you also want to show the top-N share, present it as a secondary column with its own denominator, and state that it measures reach into the top, not typical performance. Set a minimum n before comparing tags.

Limitations:
- The parameters (mixture weights and lognormal spreads) were chosen so that the effect is visible. In real data the size of the flip depends on the distribution, and may be absent.
- This applies to view and rank statistics. It does not apply to co-occurrence measures such as cosine or lift, which answer a different question.
- The example uses one tag per work for simplicity. Real works often carry several tags, which changes the denominators.
